# AgentPulse v0.1 Design Document

**Date:** 2026-05-22  `
**Status:** approved

## Overview

AgentPulse is a local desktop monitor for AI coding agents. v0.1 focuses on Claude Code integration: capture lifecycle events via hooks, persist to SQLite, and display real-time status in a frameless floating window.

**Product positioning:** Local-first. No cloud sync. No source code upload. No transcript upload.

## Tech Stack

| Layer | Technology | Role |
|-------|-----------|------|
| Desktop Shell | Tauri 2 | Window management, tray, Rust runtime |
| Frontend | Vue 3 + TypeScript + Tailwind CSS | Floating window UI |
| Backend | Rust (Tauri core) | HTTP server, state machine, SQLite, process watcher |
| Database | SQLite (via rusqlite) | Events, sessions, settings |
| Communication | Tauri events (invoke/emit) | Rust ↔ Vue data flow |

## Architecture: 4 Layers

```
┌─────────────────────────────────┐
│  Floating Window (Vue3 + Tailwind)│  ← Tauri event bridge
├─────────────────────────────────┤
│  Local Monitor Core (Rust)       │  ← HTTP :17878 + SQLite + state machine
├─────────────────────────────────┤
│  Hooks In  │  File In  │ Process In │  ← v0.1: Hooks only
└─────────────────────────────────┘
```

## Unified Event Model

```typescript
type AgentSource = "claude-code";

type AgentStatus =
  | "starting"
  | "running"
  | "tool_running"
  | "waiting_input"
  | "waiting_permission"
  | "completed"
  | "failed"
  | "unknown";

interface AgentEvent {
  id: string;           // UUID v4, generated by collector
  source: AgentSource;
  sessionId: string;    // from CC hook's session_id
  cwd: string;
  projectName?: string; // derived from cwd basename
  eventType:
    | "session_start"
    | "pre_tool_use"
    | "post_tool_use"
    | "permission_request"
    | "notification"
    | "stop"
    | "failure";
  status: AgentStatus;
  message?: string;
  toolName?: string;
  transcriptPath?: string;
  createdAt: number;    // Unix ms
}

interface AgentSession {
  sessionId: string;
  source: AgentSource;
  cwd: string;
  projectName: string;
  status: AgentStatus;
  startedAt: number;
  updatedAt: number;
  completedAt?: number;
  lastMessage?: string;
  lastToolName?: string;
  transcriptPath?: string;
  needsAttention: boolean;
}
```

## Claude Code Hook Event Mapping (v0.1)

| Hook Event | AgentPulse Status | Notes |
|-----------|------------------|-------|
| SessionStart | starting → running | Create session record |
| PreToolUse | tool_running | Capture tool_name |
| PostToolUse | running | Capture tool_response summary |
| PostToolUseFailure | failed | Capture error |
| Notification (permission_prompt) | waiting_permission | needsAttention = true |
| Notification (idle_prompt) | waiting_input | needsAttention = true |
| Stop | completed | Record completedAt |

## State Machine

```
unknown → SessionStart → starting → (first event) → running
running → PreToolUse → tool_running
tool_running → PostToolUse → running
running → Notification(permission_prompt) → waiting_permission
running → Notification(idle_prompt) → waiting_input
waiting_permission → (any tool event) → tool_running
waiting_input → (any tool event) → tool_running
running → Stop → completed
tool_running → PostToolUseFailure → failed
```

`needsAttention` is true when status ∈ {waiting_input, waiting_permission, completed, failed}.

## HTTP API (Internal)

```
POST /api/events
  Body: AgentEvent (JSON)
  Response: 201 { id, sessionId }

GET /api/sessions
  Response: [AgentSession]

GET /api/sessions/:id
  Response: AgentSession

GET /api/health
  Response: 200 { status: "ok" }
```

## Hook Adapter

Claude Code hooks are configured in `~/.claude/settings.json` or project-level `.claude/settings.json`. Each hook event fires a thin adapter script (Python) that:

1. Reads hook JSON from stdin/argv
2. Normalizes to `AgentEvent` format
3. POSTs to `http://127.0.0.1:17878/api/events`

## Database Schema (SQLite)

```sql
CREATE TABLE sessions (
  session_id TEXT PRIMARY KEY,
  source TEXT NOT NULL,
  cwd TEXT NOT NULL,
  project_name TEXT,
  status TEXT NOT NULL DEFAULT 'unknown',
  started_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  completed_at INTEGER,
  last_message TEXT,
  last_tool_name TEXT,
  transcript_path TEXT,
  needs_attention INTEGER DEFAULT 0
);

CREATE TABLE events (
  id TEXT PRIMARY KEY,
  session_id TEXT NOT NULL,
  source TEXT NOT NULL,
  event_type TEXT NOT NULL,
  status TEXT NOT NULL,
  cwd TEXT,
  message TEXT,
  tool_name TEXT,
  transcript_path TEXT,
  created_at INTEGER NOT NULL,
  FOREIGN KEY (session_id) REFERENCES sessions(session_id)
);

CREATE INDEX idx_events_session ON events(session_id);
CREATE INDEX idx_events_created ON events(created_at);
CREATE INDEX idx_sessions_status ON sessions(status);
CREATE INDEX idx_sessions_updated ON sessions(updated_at);
```

## Testing Strategy

| Layer | Tool | Scope |
|-------|------|-------|
| Rust unit | `#[cfg(test)]` + cargo test | state_machine, db, event_server handlers |
| Rust integration | cargo test (integration) | HTTP endpoint + DB round-trip |
| Vue unit | Vitest + vue-test-utils | Component rendering, store logic |
| Vue e2e | Tauri + Playwright (deferred to v0.2) | Full window flow |
| Adapter | pytest (deferred) | Hook JSON normalization |

## Key Design Decisions

1. **No Electron** — Tauri is lighter, Rust fits system-level monitoring better
2. **HTTP, not stdin** — hook adapter POSTs to local server instead of coupling directly to Tauri process; decouples hook lifecycle from app lifecycle
3. **SQLite, not JSON files** — queryable history, concurrent-safe writes from HTTP handler
4. **Hooks first, not terminal scraping** — Claude Code hooks are the authoritative event source; terminal output is unreliable
5. **Single window, multiple cards** — one floating window shows all active sessions as stacked cards; simpler than managing multiple windows per session
